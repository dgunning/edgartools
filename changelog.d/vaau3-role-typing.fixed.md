**Selecting a statement by its role URI could return a different statement.** `Statements.__getitem__` typed any unrecognized string by testing whether a canonical statement's name occurred *inside* it, so `.../CONSOLIDATEDBALANCESHEETSParenthetical` was typed `BalanceSheet` — as were 71 disclosure roles named things like `...ReflectedInTheConsolidatedBalanceSheets`. That attribute does not only classify: it also decides which role `render()` renders, so asking for Apple's balance-sheet parenthetical by its exact URI returned the primary balance sheet's 38 rows of assets and liabilities, and the parenthetical's own share counts and par values were unreachable. It also meant a note table could have its rows sign-flipped purely because its role name mentions a statement. A known role is no longer typed by its spelling — the resolver has already classified it, and `Statement.classified_type` reads that back without selecting a role; the substring test survives only for a bare statement name. Across the 2,658 roles of the fixture corpus, 2,492 render identically and 166 change: 94 roles stop being sign-gated (72 the resolver calls disclosures, 18 parentheticals, 4 unclassified) and not one of them is a primary statement, while one income statement the sniff had mistyped `ComprehensiveIncome` from its own name correctly starts being gated. No primary statement loses its signs. (bead edgartools-vaau.3)
