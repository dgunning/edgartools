**`get_financial_metrics()` rendered and converted the same three statements once per metric.** Every scalar getter funnels into one of three sibling helpers, and each carried its own copy of the same four steps — pick the statement for a type, `render(standard=True)`, `to_dataframe(presentation=False)`, drop abstract rows — so a single call did the whole rendering pipeline 14 times for Apple and 18 for JPMorgan over only three distinct configurations. The three helpers now share one `_render_statement_frame()`, and the call installs a memo for its own duration: a statement's rendering depends on the view and periods in force, so a cache outliving the call would answer a later question with an earlier one's configuration, and the memo is discarded on exit including when a getter raises. All four fixtures now render 3 times, with every metric byte-identical — JPMorgan's six legitimately absent metrics included, which is what a shared frame would most easily corrupt.
