**`facts_history(include_dimensions=True)` returned the undimensioned series.** The frame was built by a query that leaves dimensions excluded, so every `dim_*` column was projected away; the `if include_dimensions:` branch then looked for those columns in that projected frame, found none, and fell through. The flag now reaches the query. Spectrum Brands' `us-gaap:DeferredCosts` returns its filed breakdown — $12.4M and $9.6M for non-US plans against $39.9M and $31.8M consolidated — where it previously returned a frame with no dimensional column at all. Fixing this exposed a second defect in the same function: `date_col` defaults to `period_end`, but an instant fact carries only `period_instant`, so *every balance-sheet concept* dropped all of its rows and returned an empty frame; the date column now falls back to the one the facts populate, and a `date_col` that is neither raises `ValidationError` naming the two valid columns. This is a sibling of GH #1243, which PR #1259 fixed only in `get_facts_with_dimensions()`. (GH #1286, bead edgartools-n93w.5)
