**Sorting one fact query reordered the cache every other query reads from.** `FactQuery.execute()` starts from `FactsView.get_facts()`, which returns its cached list by reference, and with no filter and no transform that identity survived to `results.sort()` — so a `.sort_by()` anywhere permanently reordered the shared cache, and a later unrelated `.limit(n)` came back with different facts. Measured across 15 large 10-Ks, an independent five-fact query changed after an unrelated sort on 15 of 15 filings, and on none after. The sort now builds a new list.
