**Every iXBRL date written with an English month name was rejected unless its fields were separated by a space.** `_date_words` replaced commas with spaces and then split on whitespace, so `19-Sep-2024` stayed a single token, failed the field-count check, and the extractor exposed the raw display string with a `format_issue` instead of a date. The Transformation Registry separates those fields with a run of non-alphanumeric characters, and the numeric sibling `_date_numeric` already accepted `.`, `/`, `-` and whitespace — one rule with two implementations that disagreed. This was not confined to the reported format: all thirteen registry formats dispatching to this tokenizer rejected every separator but a space. FingerMotion's 10-K exposed four `fngr:WarrantExpiryDate` facts as `19-Sep-2024`, `4-Nov-2025`, `21-Nov-2025` and `1-Oct-2024`, which now transform to the ISO values the SEC-extracted instance carries. Across 16 filings and 40,219 iXBRL facts, no already-transformed value changed. (GH #1284, bead edgartools-xn1u.1)
