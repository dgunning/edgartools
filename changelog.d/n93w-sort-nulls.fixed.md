**`sort_by()` raised `TypeError` on most filings, and silently did nothing on a sparse column.** The comparator kept an explicit `None`, so `sort_by('numeric_value')` failed with `'<' not supported between instances of 'NoneType' and 'float'` on any filing mixing numeric and text facts — all 15 measured, Auburn National's 10-K carrying 1,733 numeric against 111 non-numeric. Separately the guard tested `sort_by in results[0]`, deciding from the first row alone, so sorting by `period_end` was skipped outright whenever the first fact happened to be an instant, leaving Auburn National's 614 populated end dates unsorted with no error. The key is now a total order over values of mixed type, and the column is looked for across the result rather than in one row. (GH #1288, bead edgartools-n93w.2)
