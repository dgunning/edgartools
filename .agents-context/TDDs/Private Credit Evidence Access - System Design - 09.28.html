Scope: Phase 1: edgar_fund fixes, bdc_nonaccrual, filing resolver, continuation, edgar_notes/edgar_read paging · Phase 2: edgar_document, edgar_text_search and edgar_filing changes · Commits land on the current branch

Reviewers: [TBD]

The functional spec asks the MCP to hand analysts complete, dated and sourced evidence about BDC loans and lender protections, without interpreting it. This design does that with one new tool for reading filed documents and exhibits, extensions to five existing tools, and two shared services: one picks exactly the filing the caller asked for, and one lets any long result be continued page by page. Most of the extraction logic already exists in the library; the work is mainly in the MCP layer.

Design problems and approaches

Three decisions are expensive to reverse once agents depend on them. How provenance and gap fields are shaped was deliberately dropped as a cross-cutting decision during framing. Each tool specifies its own fields (see Components).

Settled without a real alternative (no trade-off analysis needed):
  • Borrower-name bug: fund.py:550–565 tests hasattr(inv, 'name'), but the model field is company_name. The fix is to emit company_name and identifier.
  • Dropped fields: serialize principal_amount, pik_rate, spread, shares and percent_of_net_assets, which the model has and the tool discards.
  • Totals: full-extraction totals and filtered or page totals are reported under separate keys (F3).
  • Non-accrual: the evidence is exposed through the existing extract_nonaccrual(filing), which already returns extraction_method and warnings (F4).
  • Text search: edgar_text_search surfaces file_type, file_description and document_id. EFTSResult already has these fields; the MCP drops them.

1. Tool surface: extend existing tools or add new ones

At stake: F7 says selecting an exhibit must never quietly return the parent filing instead, and F9 requires agents to find the workflow without help. Both depend on whether document-level work gets its own tool or is layered onto tools built around other ideas.

A. Extend existing tools only rejected

New parameters on edgar_fund, edgar_notes and edgar_filing, plus a document parameter on edgar_read for exhibits. The tool count stays at 13.

  • + No new tool for agents to learn.
  • − edgar_read is organized by section. On failure it falls back to raw_text_preview of the whole filing (reader.py:216–223), which is exactly the silent fallback F7 forbids.
  • − Exhibit list, search and read would all overload one sections parameter.

B. New dedicated tools rejected

A new edgar_bdc (holdings, non-accrual) split out of edgar_fund, plus a new edgar_document. 15 tools.

  • + Cleanest parameter schemas.
  • − Duplicates the existing bdc_search/bdc_portfolio actions. Keeping them for compatibility means two paths to one result.
  • − More tools to choose between means more routing mistakes.

C. Hybrid recommended

Extend edgar_fund (new bdc_nonaccrual action and selection parameters), edgar_notes, edgar_read, edgar_filing and edgar_text_search. Add one tool, edgar_document, for listing, searching and reading a specific document or exhibit. 14 tools.

  • + BDC evidence stays where agents already find it.
  • + Exhibits get a tool whose only job is document identity, so it cannot fall back to a filing summary.
  • − One more tool, and it partly overlaps edgar_read. The descriptions must say which to use.

Recommendation: C (hybrid). Correctness is the tie-breaker. F7's rule that an exhibit must not resolve to the parent filing is easiest to guarantee in a tool that has no parent-filing mode at all. Everything else extends where agents already go, which satisfies the additive-only constraint.

2. Filing selection: how a caller names "the right document"

At stake: F1 requires holdings, notes and sections to come from the filing the caller asked for, and an impossible selection must fail rather than return a different filing. Today, reference.py:178–237, notes.py:104–127 and reader.py:165–180 each pick the latest filing on their own.

A. Accession number only rejected

Historical access means passing an accession_number. When it's absent, tools keep the current "latest" behavior.

  • + Completely unambiguous and trivial to implement.
  • − Analysts think in periods ("Q3 2025"). Every request needs an extra discovery call.

B. Period selectors, resolved in each tool rejected

Each tool accepts period or fiscal_year/quarter and resolves it itself.

  • + Natural for analysts.
  • − Four separate implementations will drift apart. A "nearest match" shortcut in any one of them breaks F1 without anyone noticing.
  • − Fiscal quarters are ambiguous: Q4 has no 10-Q, and fiscal years don't all end in December.

C. Both, through one shared resolver recommended

resolve_report_filing(identifier, form, accession_number, period) in the MCP layer. An accession number takes precedence. A period (YYYY-MM-DD) must exactly match period_of_report on an original filing, or the call fails with the available periods listed. With neither, the latest filing is used and the response says so.

  • + One implementation that is tested once, and every response states how the filing was selected.
  • − A new shared module, and every tool that selects a filing has to use it.

Decided: amendments stay selectable only by accession number, so a period request never lands on a partial /A filing (current policy at filing.py:104–106). The BDC library also gains a way to extract from a specific filing (see Components), so the MCP doesn't bypass BDCEntity's fallback logic.

3. Continuation: letting a caller reach everything, a page at a time

At stake: F3, F5 and F7 require every extracted holding and every readable passage to be reachable. The measured cost of about 11 s per extraction, with nothing reused across calls, decides whether paging is usable. Each page must also come from the same underlying result as the page before.

A. Stateless offset/limit rejected

The caller passes offset and the server re-extracts on every call.

  • + Simplest; no state.
  • − About 11 s per page, so all ARCC holdings take over 10 minutes.
  • − No way to detect that the result changed between pages, for example after a library upgrade mid-session.

B. Server-side session results rejected

The cursor is only an ID for a result held in server memory.

  • + Fast.
  • − Breaks after a restart, and under streamable-http (server.py:436) it breaks whenever a different process handles the call.
  • − An expired ID leaves the caller stranded partway through.

C. Self-describing cursor + in-process cache recommended

The cursor carries everything needed to rebuild the page: tool, accession number, document, filter, offset and a fingerprint of the result. A bounded in-memory LRU cache makes later pages fast. On a cache miss the server re-extracts and checks the fingerprint.

  • + Pages after the first are fast whenever the cache hits.
  • + Survives restarts and multiple processes, at the cost of one slower page.
  • + A mismatched fingerprint returns an error instead of skipping or repeating records.
  • − Cursor encoding and validation, and cache memory that has to be bounded.

System architecture

An agent asks a question and calls MCP tools. Those tools use two new shared services to choose the right filing and to page through long results. The services then call library code that already does the extraction. Tags show what's new, what changes and what's reused as-is.

Every data path is tool → resolver → library → SEC, and the continuation service sits between the tool and the library for anything longer than one page. No tool compares periods, links filings together or reads meaning into clauses. That line in the spec maps onto these module boundaries.

Data flow

Flow A: two-period borrower research (F1–F4, F8)

  1. edgar_fund bdc_search finds the BDC and returns name, CIK and ticker.
  2. edgar_search or edgar_company lists the BDC's 10-K/10-Q filings with period_of_report (via the extended format_filing_summary).
  3. edgar_fund bdc_portfolio (period="2026-06-30", borrower="ivy hill") calls the filing resolver, which returns exactly one filing, or PERIOD_NOT_FOUND with the available periods listed.
  4. The continuation service checks ResultCache. On a miss, BDC filing-scoped extraction parses the XBRL (about 11 s for ARCC) and the result is cached with its fingerprint.
  5. The tool filters on company_name and identifier, slices one page and returns records, source, page and extraction (coverage, rate convention). Totals for the full portfolio and for the filtered subset are kept separate.
  6. The caller follows next_cursor. The cursor is decoded and checked against the fingerprint, and the next page is served from cache.
  7. The caller repeats steps 3–6 with a second period. The comparison itself happens in the caller. The MCP never asserts that two records are the same loan.
  8. edgar_fund bdc_nonaccrual (same period) calls the resolver, then extract_nonaccrual(filing), and returns evidence_level, the investments with footnote text, warnings and interpretation_limits.

Flow B: recovery-document research (F6, F7, F8)

  1. edgar_text_search (query="guaranty" "collateral agreement", identifier=…) returns filings with the matching document_id and file_type (such as EX-10.1).
  2. edgar_document list (accession number) returns documents and exhibits, with a note that agreements may be incorporated from earlier filings. The caller can read the exhibit index section or use edgar_text_search to find the original filing.
  3. edgar_document search (document="EX-10.1", query="guarant") runs Filing.grep on that document only and returns matches with char_offset locators.
  4. edgar_document read (around=<locator>) returns a 6,000-char page centered on the provision, with next_cursor. The text is cached by accession number and document.
  5. If an external_reference points to another accession number, the caller repeats steps 2–4 on that filing. The MCP doesn't claim to have rebuilt the full amendment history.
  6. If the document is a PDF or image, read returns identity, url and unreadable_reason. It never returns an empty string that looks like "no protections".
